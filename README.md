# ห้องเรียนเทคโนโลยี ม.3 (Gamified LMS)

เว็บห้องเรียนออนไลน์แบบเกม รายวิชาพื้นฐานวิทยาศาสตร์และเทคโนโลยี — เทคโนโลยี (การออกแบบและเทคโนโลยี) ม.3
ตามหนังสือเรียน สสวท. (หลักสูตรฉบับปรับปรุง พ.ศ. 2560) · 3 หน่วย · 20 คาบ (คาบละ 2 ชั่วโมง)

- **นักเรียน** เข้าด้วยรหัสนักเรียนอย่างเดียว เรียนตามคาบ (6 ขั้นตอน) เล่นเกม ส่งงาน ทำ Exit ticket/ข้อสอบ ดูคะแนน XP เลเวล เหรียญ ลีดเดอร์บอร์ด
- **ครู** เปิด/ปิดคาบรายห้อง แก้เนื้อหา ตรวจงาน สมุดคะแนน (ส่งออก ปพ.5) คลังข้อสอบ วิเคราะห์ข้อสอบ แก้เกม เช็คชื่อ

เทคโนโลยี: React + Vite + TypeScript · Tailwind CSS · Supabase (Postgres, Anonymous Auth, RLS, Storage, Realtime) · Vercel

> ⚠️ **เนื้อหาบทเรียน ข้อสอบ และเกมที่ติดมากับระบบเป็นฉบับร่างจาก AI** เรียบเรียงใหม่ตามหัวข้อหนังสือเรียน ครูควรตรวจทานก่อนใช้จริง
> (ข้อสอบทุกข้อติดป้าย "ร่างจาก AI ยังไม่ตรวจ" จนกว่าครูกด "ตรวจแล้ว")

## ติดตั้งและเปิดใช้งาน (ทีละขั้น)

ใช้เวลาประมาณ 20–30 นาที ไม่ต้องเขียนโค้ด ต้องมีบัญชี **GitHub**, **Supabase**, **Vercel** (สมัครฟรีได้ทั้งหมด ใช้บัญชี GitHub ล็อกอินอีกสองที่ได้)

### ขั้นที่ 1 — สร้างโปรเจกต์ Supabase

1. ไปที่ [supabase.com/dashboard](https://supabase.com/dashboard) → **New project**
2. ตั้งชื่อ (เช่น `tech-m3`) ตั้งรหัสผ่านฐานข้อมูล (จดเก็บไว้) เลือก Region **Southeast Asia (Singapore)** → Create
3. รอจนโปรเจกต์พร้อม (1–2 นาที)

### ขั้นที่ 2 — เปิด Anonymous Sign-ins

1. เมนู **Authentication → Sign In / Providers** (หรือ Authentication → Settings)
2. เปิด **Allow anonymous sign-ins** → Save

> ระบบใช้ "ผู้ใช้ไม่ระบุตัวตน" ประจำเบราว์เซอร์ แล้วตรวจรหัสนักเรียน/รหัสครูที่เซิร์ฟเวอร์ (ไม่มีรหัสผ่าน และไม่มีการตรวจรหัสในโค้ดฝั่งหน้าเว็บ)

### ขั้นที่ 3 — สร้างฐานข้อมูล (รันไฟล์เดียว)

1. เมนู **SQL Editor** → **New query**
2. เปิดไฟล์ [`supabase/setup_all.sql`](supabase/setup_all.sql) คัดลอก **ทั้งไฟล์** ไปวาง → กด **Run**
3. ต้องขึ้น `Success` — ได้ตารางทั้งหมด + RLS + ห้อง ม.3/1 + นักเรียนตัวอย่าง 5 คน (รหัส `10001`–`10005`) + 3 หน่วย 20 คาบ + เนื้อหาร่าง + งาน + ข้อสอบ 150 ข้อ + เกม 17 เกม + เหรียญ 8 เหรียญ
4. ตรวจ Realtime: เมนู **Database → Publications → supabase_realtime** ต้องมีตาราง `leaderboard_ticks` (ถ้าไม่มี ให้ติ๊กเพิ่ม)

> ⚠️ `setup_all.sql` ใช้กับโปรเจกต์ที่ยังว่างเท่านั้น ถ้ารันซ้ำจะ error เพราะตารางมีอยู่แล้ว (ข้อมูลเดิมไม่เสียหาย)

### ขั้นที่ 4 — คัดลอกคีย์ Supabase

เมนู **Project Settings → API** (หรือ Data API / API Keys) จดไว้ 2 ค่า:

| ค่า | ใส่ในตัวแปร |
| --- | --- |
| Project URL (เช่น `https://abcd.supabase.co`) | `VITE_SUPABASE_URL` |
| `anon` / `publishable` key | `VITE_SUPABASE_ANON_KEY` |

> 🔒 **ห้ามใช้ `service_role` / secret key ในเว็บเด็ดขาด** — คีย์นั้นข้าม RLS ได้ทั้งหมด

### ขั้นที่ 5 — อัปโหลดโค้ดขึ้น GitHub

1. ไปที่ [github.com/new](https://github.com/new) สร้าง repository (เลือก **Private** ได้)
2. ในเครื่อง เปิดโฟลเดอร์โปรเจกต์แล้วรัน:
   ```bash
   git init
   git add .
   git commit -m "first commit"
   git branch -M main
   git remote add origin https://github.com/<ชื่อบัญชี>/<ชื่อ-repo>.git
   git push -u origin main
   ```
   (ไฟล์ `.env` ถูกกันไว้ใน `.gitignore` แล้ว จะไม่ขึ้น GitHub)

### ขั้นที่ 6 — Deploy บน Vercel

1. ไปที่ [vercel.com/new](https://vercel.com/new) → **Import** repository ที่สร้างไว้
2. Framework Preset: **Vite** (ระบบเลือกให้เอง) · Build Command `npm run build` · Output `dist`
3. เปิด **Environment Variables** ใส่ 2 ค่าจากขั้นที่ 4: `VITE_SUPABASE_URL` และ `VITE_SUPABASE_ANON_KEY`
4. กด **Deploy** รอ 1–2 นาที จะได้ลิงก์ เช่น `https://tech-m3.vercel.app`

> แก้ค่า env ภายหลัง ต้องกด **Redeploy** ด้วย เพราะค่าถูกฝังตอน build

### ขั้นที่ 7 — ตั้งค่าครั้งแรก (สำคัญ)

1. เปิดเว็บ → กดลิงก์ **สำหรับครู** → พิมพ์รหัสครูเริ่มต้น `superurrwnm`
2. ไปที่ **ตั้งค่า → เปลี่ยนรหัสสำหรับครู** ตั้งรหัสใหม่ทันที (รหัสเริ่มต้นอยู่ในไฟล์บน GitHub ใครก็เห็นได้)
3. ตั้งค่า ชื่อโรงเรียน ภาคเรียน ปีการศึกษา สัดส่วนคะแนน เกณฑ์เกรด การหักส่งช้า
4. **นักเรียน** → ลบ/ปิดใช้งานนักเรียนตัวอย่าง แล้ว **นำเข้าจาก Excel** (ดาวน์โหลดแม่แบบในหน้า)
5. **คลังข้อสอบ** → ตรวจทานข้อสอบ กด "ตรวจแล้ว" · **เกม** → ตรวจเนื้อหาเกม (ทดลองเล่นได้)
6. **งาน / ตรวจงาน** → ตั้งกำหนดส่ง · **ชุดสอบ** → ตั้งเวลาเปิด-ปิดกลางภาค/ปลายภาค

✅ เสร็จ! ในชั่วโมงเรียน: ครูเปิด **บทเรียน / คาบเรียน** กด 🔒 เปิดคาบให้ห้องนั้น → นักเรียนกรอกรหัสเข้าเรียน (ระบบเช็คชื่อ +10 XP อัตโนมัติ)

**รูปแบบเนื้อหาบทเรียน:** `## หัวข้อ` = การ์ดใหม่ · `:::tip` … `:::` = เกร็ดน่ารู้ · `:::doctor` … `:::` = ด็อกเตอร์อธิบาย · `:::example` … `:::` = ตัวอย่างใกล้ตัว · `:::think` คำถาม `---` แนวคิด `:::` = กล่องลองคิดดู (นักเรียนกดดูแนวคิดเอง) · `:::embed <ลิงก์ YouTube/Canva>` = ฝังวิดีโอ/สไลด์

**แก้เนื้อหาบทเรียนจำนวนมาก:** แก้ไฟล์ `supabase/lessons/NN.md` (NN = เลขคาบ) → `npm run seed:build` → รัน `supabase/updates/lessons_update.sql` ใน SQL Editor (ทับเนื้อหาบทเรียนแรกของคาบที่ระบุ)

**คะแนน (ค่าเริ่มต้น 100):** งานรายคาบ 30 · โครงงาน 15 · ทดสอบท้ายหน่วย 15 · กลางภาค 20 · ปลายภาค 20 — ระบบแปลงผลรวมคะแนนเต็มจริงของแต่ละหมวดเป็นสัดส่วนในตั้งค่าเอง เพิ่ม/ลดงานได้ไม่ต้องคิดเลข

**XP:** เกม +10–50 (รอบแรกเต็ม รอบต่อไป 20% วันละ 3 รอบ) · ส่งงานตรงเวลา +30 · Exit ticket เต็ม +20 · เข้าเรียน +10 · ทุก 200 XP ขึ้น 1 เลเวล

## ความปลอดภัย

- เบราว์เซอร์ทุกเครื่องได้ `auth.uid()` แบบ anonymous · ตรวจรหัสใน RPC `login_with_code` (SECURITY DEFINER) เท่านั้น
- รหัสครูเก็บเป็น bcrypt hash ในตาราง `app_secrets` ที่ไม่มี role ใดอ่านผ่าน API ได้
- กรอกรหัสผิดเกิน 10 ครั้งใน 5 นาทีต่อเบราว์เซอร์ → ล็อก 5 นาที (Supabase จำกัดการสร้างผู้ใช้ anonymous ต่อ IP อีกชั้น — เปิด CAPTCHA ใน Supabase Auth ได้ถ้าต้องการเข้มขึ้น)
- **ทุกตารางเปิด RLS** — นักเรียนอ่าน/เขียนได้เฉพาะของตัวเอง เห็นเนื้อหาเฉพาะคาบที่ปลดล็อกของห้องตัวเอง แก้คะแนนตัวเองไม่ได้
- **เฉลยข้อสอบไม่ถูกส่งไปเครื่องนักเรียน** ก่อนส่งข้อสอบ (นักเรียนอ่านตาราง `questions` ไม่ได้ ได้คำถามผ่าน `start_exam`) และตรวจคะแนนที่เซิร์ฟเวอร์
- ไฟล์งานเก็บใน bucket `submissions` (private) ในโฟลเดอร์ของนักเรียนเอง รูป/PDF ไม่เกิน 10 MB
- ตั้ง security headers (CSP, X-Frame-Options ฯลฯ) ใน `vercel.json`
- ข้อจำกัด: คะแนนเกมคิดบนเครื่องนักเรียน จึงปลอมได้ในกรอบ 0–100 + เวลาเล่นขั้นต่ำ + XP สูงสุดต่อเกม — กระทบเฉพาะ XP/ลีดเดอร์บอร์ด ไม่กระทบคะแนนเก็บหรือเกรด

## สำหรับนักพัฒนา

```bash
npm install
cp .env.example .env      # ใส่ VITE_SUPABASE_URL และ VITE_SUPABASE_ANON_KEY
npm run dev               # http://localhost:5173
```

| คำสั่ง | ใช้ทำอะไร |
| --- | --- |
| `npm run dev` | เปิดเว็บสำหรับพัฒนา |
| `npm run build` | ตรวจ TypeScript (strict) + build |
| `npm test` | unit test (Vitest): คะแนน เกรด ตัวตรวจคำตอบเกม/ข้อสอบ นำเข้า Excel และเปิดหน้าเกม/บทเรียนจาก seed ทุกชิ้น |
| `npm run test:db` | ทดสอบ migration + **RLS** + RPC ทั้งหมดบน Postgres จำลอง (PGlite) — เช่น นักเรียน A อ่านงานนักเรียน B ไม่ได้, เฉลยไม่รั่ว, กันโกง XP |
| `npm run seed:build` | สร้าง `seed_questions.sql`, `seed_games.sql`, `setup_all.sql` ใหม่ หลังแก้ไฟล์ต้นฉบับ |

**ไฟล์ต้นฉบับเนื้อหา:** ข้อสอบ `supabase/questions/questions.txt` · เกม `supabase/games/games.json` · เหรียญ `supabase/games/badges.json` · บทเรียน/คาบ/งาน `supabase/seed.sql`

**อัปเดตฐานข้อมูลที่ติดตั้งแล้ว:** รันเฉพาะไฟล์ใหม่ใน `supabase/migrations/` ตามลำดับเลข (ใน SQL Editor) หรือใช้ Supabase CLI:
`npx supabase init` (ครั้งแรก) → `npx supabase link --project-ref <ref>` → `npx supabase db push`

**โครงสร้าง**

```
src/
  app/          router, AuthContext, guards, หน้า error
  lib/          supabase client, scoring.ts, grade.ts, levels.ts, itemAnalysis.ts

  games/        shared (GameShell, schemas, logic, sfx) + engine เกม 7 แบบ + registry
  components/   UI กลาง, ตัวละคร SVG (ด็อกเตอร์ น้ำหวาน นนท์ ...)
supabase/       migrations/, seed*.sql, setup_all.sql, questions/, games/, tests/
scripts/        สร้างไฟล์ seed
```
